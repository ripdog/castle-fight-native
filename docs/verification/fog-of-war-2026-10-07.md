## Engine and presentation

The simulation owns team visibility, exploration, stationary reveal deadlines/detection, and enemy structure memory. Its deterministic visibility grid uses integer circle tests and ground sight lines against cliff levels/authored blockers; air and explicit script modifiers bypass those sight lines. Configuration identity includes fog rules; canonical checksums include persistent history and grants. Snapshot schema 21, checksum schema 26, and content bundle schema 9 reject incompatible state.

Observer presentation filters actors, corpses, missile positions, events, inspection, and targets. Losing sight removes a rendered enemy without creating a fake death or missile impact. Structure silhouettes carry only observed identity/ownership/footprint and frozen observed construction phase. Rejoin restores silhouettes even when their live structure has since disappeared behind fog.

The client uses a world-space depth reconstruction and an RG visibility/exploration texture. A separable spatial blur and linear sampling soften edges. An exponential fade smooths both reveal and conceal without changing binary gameplay visibility. Both single-sample and multisampled depth variants are supported. Profiling/stress views remain omniscient.

## Verification and practical limits

Focused synthetic tests cover exploration retention, allied sight and acquisition, moving/expiring Faerie Fire, terrain-only revelation versus invisible detection, area radius/expiry, save/wire restore across worker counts, hidden structure destruction/rescouting, day/night boundaries, air/ground occlusion, malformed snapshot rejection, fogged attack flashes, frozen construction memory, native spell acquisition/detection, observer filtering, and cosmetic fade/blur behavior. Catalog-wide coverage checks all playable sight sources against the generated projection; Python checks regenerate the committed artifacts from retained evidence.

A headless GPU test renders shroud, explored fog, and visible terrain and checks pixel brightness. It saves `target/fog-gpu-verification.png`. Run it explicitly with `tools/cargo-interactive test -p castle-fight-client fog::tests::gpu_composite -- --ignored --nocapture`. The isolated GUI workspace tool is unavailable on this host, so interactive camera/gameplay QA has not been performed.

Warcraft's proprietary visibility raster and occlusion implementation are not available. The engine reproduces the extracted sight/reveal rules using its deterministic grid; exact cell-for-cell occlusion equivalence to Warcraft has not been verified. The retained Castle Fight projection currently supplies no destructible sight blockers. New destructibles, additional true-sight abilities, or modes with different script fog lifecycles require their own versioned evidence and behavior binding. This feature does not expand the supported roster or match-mode surface.

## Validation results

Passed: 785 workspace tests, strict workspace/all-target Clippy (`-D warnings`), formatting, and 13 runtime-catalog/release-manifest Python tests. The explicit GPU test passed both single-sample and four-sample depth. Previous snapshot/content revisions are incompatible with the new persistent fog state.

The reproducible visibility-only profiler is `tools/cargo-interactive run -p castle-fight-sim --example profile_fog`. It places stationary sources with imported Footman sight across retained map bounds and cliff geometry, excludes movement/collision bodies, and verifies readback does not mutate the checksum. On this host, optimized development builds averaged approximately 1.7 ms / 7.9 ms / 12.8 ms per readback for 1,000 / 5,000 / 10,000 sources. Conservative skipping of fully visible rows reduced the same workload from approximately 2.8 ms / 15.9 ms / 28.9 ms. These are visibility readback timings, not whole-tick/frame budgets; the simulation refreshes sight at two phase boundaries and the client also requests readback.
