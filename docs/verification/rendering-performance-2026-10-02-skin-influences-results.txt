Implementation scope: classify highest nonzero weight slot from extracted Mesh snapshots; metadata-only layout markers; delegate complete StandardMaterial/WC3 alpha/team specialization; derive main/prepass vertex and current/previous skinning functions from loaded engine sources. Eligible 1/2/3-slot variants omit exactly-zero trailing matrix terms and use corresponding prefix weight-input formats at the original stride/offset. This input-layout difference is required to distinguish variants in Bevy's second-level pipeline cache. Driver-filled missing components are ignored. Vertex bytes, full skin/joint/palette ownership, bounds, normals/tangents, fragments, material handles and bindings remain unchanged. Custom vertex shaders, unknown materials and shared material properties keep the ordinary four-slot path.

Crash cause: sample_skin_pipelines read a descriptor for pipeline ID 18 while PipelineCache.pipelines was still empty. IDs can already exist in the material specialization cache while queued in new_pipelines. Bevy explicitly documents get_render_pipeline_descriptor as panicking for IDs not processed by process_queue. The counter now first uses get_render_pipeline, whose bounds-checked lookup returns None for queued, compiling and failed pipelines. Only ready pipelines reach descriptor lookup; the counter label explicitly says ready cached main-view instances. The renderer itself and authoritative simulation are unchanged by this sampling fix.
